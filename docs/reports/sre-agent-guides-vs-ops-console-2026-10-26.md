# SRE-agent guides vs ops-console (2026-10-26)

Read-only research. Sources are the primary pages listed in each row; nothing below rests on a secondary summary. Compared against `docs/plans/ops-console.md`, `../ops-console/README.md`, `agent/triage.mjs`, `agent/ask.mjs`, `agent/actions.mjs`, `agent/probes.mjs`, `agent/runbook.md`.

## Verdict

Nothing in the Anthropic or OpenAI guidance argues for changing the ops-console design. Every structural rule the guides state, ops-console already follows, and in two places it is stricter than the published examples: the model has no write tool at all (the SRE cookbooks give it one and gate it by prompt), and detection is deterministic shell with the model only behind a page or a question (Anthropic's on-call kit: "Claude is never the detector"). The one real gap is a feedback loop: Anthropic's own on-call setup keeps a `lessons.md` the agent reads before every investigation and appends to after each incident, promoting recurring patterns into playbooks; ops-console's runbook is hand-edited. That is a small addition. The rest is minor hardening. Managed Agents, the Agent SDK permission system, classifier auto-approval, multi-agent orchestration and OpenAI's guardrail stack are built for bigger teams or untrusted users and would add cost and surface for one operator and one Telegram chat.

## Already done

- **Deterministic detection; the model only behind a page or a question.** [oncall-kit](https://github.com/anthropics/oncall-kit): "Claude is never the detector"; "An agent that re-investigates and posts on every cycle is explicitly out of scope". [Claude on call](https://claude.com/resources/articles/ai-ci-cd-on-call): alert rules fixed, investigation agentic.
- **Narrow read-only tools with validated arguments, no shell.** Fixed ssh commands and zod enums in `probes.mjs`. [Building effective agents](https://www.anthropic.com/research/building-effective-agents): "Poka-yoke your tools". [CISO's guide](https://claude.com/blog/ciso-guide-to-agentic-ai): "grant the narrowest capability that still completes the task"; an agent "will never attempt an action that isn't in its tool list".
- **Human tap before any change, approval checked in code, replay-proof.** Single-use nonce, 5-minute expiry, chat id and sender id both checked. [Agents SDK human-in-the-loop](https://openai.github.io/openai-agents-python/human_in_the_loop/): validate decisions "against server-held pending items, and prevent replayed submissions". [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) p. 30: high-risk actions need oversight "until confidence in the agent's reliability grows", which is the plan's "the action log earns v2".
- **Iteration and probe caps enforced by the tools, not the prompt.** [Building effective agents](https://www.anthropic.com/research/building-effective-agents): include "a maximum number of iterations".
- **Runbook from past incidents, numbers only from probe output.** [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) p. 10: "use existing operating procedures". [Claude on call](https://claude.com/resources/articles/ai-ci-cd-on-call): "query data before theorizing".
- **Action log, follow-up verification, secrets off the repo, output redaction, spend cap.** [CISO's guide](https://claude.com/blog/ciso-guide-to-agentic-ai) on audit trails; [sev_bot](https://developers.openai.com/cookbook/examples/agents_api/apps/sev_bot/readme): credentials "stay outside the sandbox"; [Claude Code hooks](https://code.claude.com/docs/en/hooks): redact inbound tool results.
- **Single agent, simplest thing.** [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf) p. 11: "maximize a single agent's capabilities first". [Building effective agents](https://www.anthropic.com/research/building-effective-agents): "the simplest solution possible".

## Do not adopt

- **Managed Agents or the Claude Agent SDK as the runtime.** Both sandbox a general-purpose agent with bash and file tools and fence it with [permission policies](https://platform.claude.com/docs/en/managed-agents/permission-policies) or the [SDK permission flow](https://code.claude.com/docs/en/agent-sdk/permissions). ops-console never gives the model bash, so there is nothing to fence, and the agent needs ssh keys on the bastion anyway.
- **Classifier-based approval (`auto` policy, SDK `auto` mode).** The Managed Agents docs: "`auto` is not a human checkpoint... If a person must review a tool's calls before they run, configure `always_ask`". One action, one operator: the confirm button is the right policy.
- **Agent-written post-mortems and fix PRs** ([Agent SDK cookbook](https://platform.claude.com/cookbook/claude-agent-sdk-03-the-site-reliability-agent), [Managed Agents cookbook](https://platform.claude.com/cookbook/managed-agents-sre-incident-responder)). Both record the agent claiming verification it did not do. The one-line lesson in rec. 1, confirmed by Raghav, is the version that fits.
- **Orchestrator with executor subagents** ([Claude on call](https://claude.com/resources/articles/ai-ci-cd-on-call)). Four probes over ssh finish in under a minute; parallelism would multiply spend for nothing.
- **OpenAI's guardrail stack** (relevance and safety classifiers, moderation, PII filters, [Agents SDK guardrails](https://openai.github.io/openai-agents-python/guardrails/)). Built for untrusted end users talking to the agent. The only user is Raghav, and `redact()` covers the one PII concern.
- **Persisted pending approvals and alert dedup** ([sev_bot](https://developers.openai.com/cookbook/examples/agents_api/apps/sev_bot/readme)). A pending restart dies with the process after 5 minutes by design, and Kuma already pages once per WARN edge.
