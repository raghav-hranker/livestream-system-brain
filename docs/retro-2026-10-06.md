# Retro 2026-10-06 — where agents lose time in this system

Sources: the 12 most recent system-brain sessions (10-03 → 10-06): dashboard daily rollup, sections
reconciliation (×2), Mongo disk space, practice-summary perf, PDF downloadable triage, live-schedule perf,
manage-classes picker perf, prod OOM investigation, Mongo slow-query script hunt, Q-Hub attach-audio,
Q-Hub composer strip + Courses row layout, transcode size estimate. Claims about the environment below were
re-checked against the checkouts on 2026-10-06.

Ordered by cost per session. "Calls" = tool calls spent before the fact was in hand.

## 1. The backend fork's `origin` cannot fetch — 7 of 12 sessions hit it

`../quicktricks-backend` has `origin = git@github.com:abhi092515/quicktricks-backend.git`; no key is
loaded for plain `github.com`, so every `git fetch origin` fails with `Permission denied (publickey)`.
Each session then greps memory until it finds the `git@raghav-hranker:` alias (recorded in
`referral-signup-cap.md`, of all places) and fetches by full URL. 2–4 calls per session, every session,
plus a stale `origin/quicktricks-admin` ref in the sessions that gave up.

**Fix (environment, not docs):** one command, covers all 109 worktrees since they share the remote config:

```sh
git -C ~/Projects/quicktricks-backend remote set-url origin git@raghav-hranker:abhi092515/quicktricks-backend.git
```

Then delete every "push via the raghav-hranker alias" line from memory — the lookup stops existing.

## 2. The fork checkouts are stale and dirty; every session rebuilds a worktree by hand

Verified today: `quicktricks-backend` on `agent/course-qa`, 32 ahead / **505 behind** origin, 127 dirty
files (incl. `dist/`). `quicktricks-admin` **172 behind**, 3 dirty. Memory
`quicktricks-admin-stale-checkout.md` still says "both reset to origin 2026-09-16" — wrong.

Consequence in 9 sessions: 3–7 calls to discover the checkout is unusable (`git status`, `git log`,
`git worktree list`), then `git show origin/quicktricks-admin:<path>` for every file read, then a fresh
worktree with a hand-copied recipe (symlink `node_modules`, copy `.env.development` / `.env.local`,
unset upstream, add a `launch.json` entry). The recipe was copied from a *different* worktree each time
(`qtb-trending`, `qt-backend-voice-m4a`, …).

**Fix:** make the worktree the first-class path and script it.
- `scripts/qt-worktree.sh <backend|admin> <name>`: fetch, `worktree add` off `origin/quicktricks-admin`
  under `~/Projects/worktrees/qt-<side>-<name>`, symlink `node_modules`, copy the env file, unset upstream,
  print the path. (`qt-tasks.sh mkwt` does half of this but only off an integration worktree.)
- CLAUDE.md, one line under the fork deploy note: *Fork work starts in a worktree:
  `scripts/qt-worktree.sh`; the `../quicktricks-*` checkouts are not the deployed code.*
- Rewrite `quicktricks-admin-stale-checkout.md` to say exactly that, or delete it.

## 3. Worktree and clone sprawl

109 backend worktrees, 66 admin worktrees, ~30 `quicktricks-*`/`nodejs-server-*`/`qtb-*` clones as
siblings under `~/Projects`, 8 entries in `.claude/launch.json`. Agents `ls ~/Projects` to orient, grep
across all of it, and get hits from dead worktrees (sections session: a match in
`worktrees/qt-pdf-outline-backend-08/…`). Listing alone costs a call and ~1 KB of context each time.

**Fix:** `git worktree prune` + `qt-tasks.sh rmwt` for merged tags; delete finished sibling clones
(`quicktricks-backend-{upgrade-docs,upgrade-visibility,wt-videopos,plan-extension,…}`); trim
`launch.json` to the live previews. Keep the survivors listed nowhere — `git worktree list` is the index
once it is short.

## 5. Auto-mode blocks on prod reads and pushes are predictable; agents still retry

8 of 12 sessions had a call denied by the auto-mode classifier ("Production Reads" / "Production Deploy"),
usually followed by one or two rephrased retries, then a pasted `!` command for the user. Several memories
say "auto mode blocks it" in passing; nothing says what to do instead.

**Fix:** a single line in CLAUDE.md: *In auto mode a prod read, ssh, or push to a fork is denied on the
first try. Write the command or script to `reference/scripts/`, hand the user one `!` line, and continue
with the non-prod work.* This retires the retries and the ad-hoc scratchpad scripts in one go.

## 6. Reusable scripts die in `/private/tmp` scratchpads

The slow-query session spent 14 calls and six whole-transcript sweeps to recover `top.js` and
`monitor.js` from another project's scratchpad, after answering "I couldn't find it". The disk-space
session wrote `mongo_disk.sh` to its scratchpad and it is gone too. `reference/scripts/` now has
`mongo-top.js` and `mongo-live.js`, but nothing indexes them.

**Fix:** the CLAUDE.md line from §5 covers the "where" rule. Add `reference/scripts/README.md`: one line
per script (what it reads/writes, the run command). Add a MEMORY.md line *Mongo diagnostics →
reference/scripts/mongo-top.js, mongo-live.js*. Also commit the 86 untracked files under `reference/` so
`git log -S` can find them.

## 7. No code map for the forks — the biggest per-session cost

The forks have a 656-line `CONTEXT.md` (vocabulary) and no `MAP.md`. Sessions spent:
- 12 calls reading the dashboard controller + 5 services + cache + prewarm, then re-reading the same
  files in the worktree (rollup).
- 2–4 calls from a screenshot string to the admin component, each time (`"Write your broadcast message"`
  → `MessagesDashboard.tsx`; "Assign PDF to Classes" → `app/admin/pdfs/manage-classes/page.tsx`).
- 6 calls to find the test runner, `src/tests/integration/setup.ts`, the reporter flag, and the known-failing
  baseline (practice-summary); 5 calls for the same in live-schedule.
- 8 calls + 3 subagents to map who writes sections/topics (sections ×2).
- 5 calls to find the `users` COLLSCAN's controller (`Notificationcontroller.ts:216`).

**Fix:** a `MAP.md` on `origin/quicktricks-admin` in each fork, so every worktree carries it:
- backend: route → controller → service → collections for the admin-facing endpoints; cron registration
  pattern (`DistributedLock`, `DISABLE_CRONS`); test command, reporter, and baseline file path.
- admin: screen label → route → page component → data hook; the picker rule (`useClasses` with `search`,
  never `useAllClasses`); the lint/tsc baseline (eslint config currently errors, tsc has pre-existing noise).
`reference/quicktricks-testing.md` (92 lines, pointed at only from the task-implementer agent files) belongs
in the backend MAP, not the brain.

## 11. Guardrails

The brain repo has no check of any kind. Two cheap ones would have caught items in §9: a `[[name]]` and
relative-link checker over `*.md` and `memory/*.md`, run from `npm run check`; and a `git status` gate that
refuses to leave `reference/` files untracked at commit time.
