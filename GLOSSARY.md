Only terms that cross a repo boundary live here. Each entry points to its **authoritative** per-repo
definition; this file never restates it. If a term lives entirely inside one repo (e.g. *FfmpegPool*,
*proactive refresh*), it is **not** here — find it in that repo's `CONTEXT.md`.

## Storage & serving combos (and which carry auth)

There is **more than one** storage/CDN combo, and they differ in their **trust boundary** — this is the single
biggest thing to get right when reasoning about playback, because `nodejs-server`'s whole premise (signed
short-lived URLs) only applies to the signed ones. Since 2026-09-09 the signed combos are modelled as a
**Media stack**: an origin axis and a CDN axis, flipped independently.

| Combo | Origin → edge | Auth at the CDN | `/playback` (nodejs-server) | Status |
|---|---|---|---|---|
| **R2 + Cloudflare** (signed) | private R2 bucket → R2 custom domain on the `hranker.org` zone, WAF rule `is_timed_hmac_valid_v0` + cache rule | **Yes** — path-embedded folder token `/v/<ts>-<mac>/<key>`, TTL fixed by the WAF rule (21600 s) | mints the Cloudflare folder token from `hlsAsset` (`RECORDED_CDN_PROVIDER=cloudflare`; live equivalent pending) | **Primary — being shipped** |
| **R2 + Bunny** (signed) | same private R2 bucket → Bunny pull zone with S3 origin auth (R2 API token, region `auto`) | **Yes** — Bunny HMAC token (query form for playback, path form for 1C input) | mints the Bunny token from `hlsAsset` | Future option (mid-class CDN rescue needs it; Bunny↔R2 S3 auth unverified) |
| **B2 + Bunny** (signed) | private B2 bucket → Bunny pull zone | **Yes** — Bunny HMAC token | mints the Bunny token from `hlsAsset` | The shipped-until-now stack; future fallback once bytes are synced R2→B2 |
| **Public R2** (unauthenticated) | R2 bucket → `R2_PUBLIC_DOMAIN` | **No** — public files; no token, no security key | not in the path; nothing to sign | Legacy; `storageProvider:'r2'` job branch |
| **Shorts public lane** (unauthenticated, *intentional*) | `recordedvideos-hranker` → the listener's `CF_HRANKER_CDN_DOMAIN`, confirmed 2026-09-16 as **`https://recordedvideos.hranker.org`** — *not* the `recordedvideos.hranker.com` code default, which serves other clients' output and so fails silently for 472; 472 is on the mirror account's hranker queue, whose `cdnDomain` overrides the default | **No** — and deliberately so: a share link that expires is not a share link | not in the path; the LMS derives a plain URL from `videoAsset` | **Shipped as the shorts contract.** Unlike Public R2 this is not legacy — it is the chosen trust boundary for promotional content (ADR-0006) |

Implications when a task crosses this boundary:
- The **origin axis** is slow to flip: the bytes must exist at the new origin, and no service syncs them. The
  **CDN axis** is cheap to flip *only when both CDNs read the same origin* — otherwise a CDN flip is chained to
  an origin flip. A mid-class CDN outage therefore has a rescue path only via R2 + Bunny, never via B2 + Bunny.
- A **403 from the CDN** diagnostic (Playback URL token expired → re-mint) applies to every signed combo; the
  token *form* differs per CDN (Bunny query/path token vs Cloudflare path token), so a client or worker must
  never parse the URL — it plays what the mint returns. Only the **Public R2** combo has no 403-on-expiry.
- The **Streamer token** / **Entitlement check** still gate *minting* on the API, but in the Public R2 combo there
  is no minted credential protecting the files — so those API gates do **not** protect the bytes.
- The origin and CDN each service is on is per-service env (`LIVE_STORAGE_*` + the live CDN provider on
  livestream; `STORAGE_*` on the 1C container; `*_CDN_PROVIDER` on the LMS). They must agree per zone — a
  livestream writing R2 while the LMS signs for a Bunny zone still pointed at B2 is a silent 404 mode. Confirm
  from the deploy's env before reasoning about auth.

## Cross-repo aliasing resolved here

- **The LMS is not real-time — by design.** nodejs-server is the system of record for class *policy*
  (`isPrivate`, `isChat`, schedule); the livestream service is the *real-time plane*. An LMS-side write
  (e.g. admin toggling `isPrivate` mid-class) is **enforced** on the next websocket firing but is **not
  broadcast** to in-room clients — only class-UI-initiated toggles notify the room. Mid-class changes
  belong in the class UI; the LMS UI sets policy for before/after class. Don't "fix" this by making the
  LMS push to livestream — the LMS must not know livestream exists.
- **"isLive" is three different things — none of them runtime truth.** `Class.isLive` is a stored
  **write-time snapshot**: the admin client computes it from `startDate`/`endDate` when constructing the
  class payload; the server stores it verbatim and the stream-status webhook never touches it. `Course.isLive`
  is a **product-type flag** (live-classes course vs recorded course). The only *runtime* liveness truth is
  `Class.streamStatus`, written by the transcoders. Don't gate anything real-time on either `isLive`.

- **`roomId` (transcoder) == `classId` (nodejs-server) == `Class._id`.** Same value, two wire names. When a
  slice crosses the webhook boundary, expect the field to be renamed at the edge — that is correct, not a bug.
- **"the secret" is per-customer, not global** — see the video-transcoder CONTEXT flag. A global secret would
  leak to unrelated customers' LMSes.
- **"the bucket combo" is not one thing.** B2 + Bunny is *signed* (Playback URL token); the R2 combo is
  *unauthenticated* (public R2 domain). They are different trust boundaries, not interchangeable storage
  backends — see "Storage & serving combos" above.
- **"public video" is two different things.** The legacy **Public-R2 combo** is protection *accidentally
  absent* — a combo that predates the signing work and is identified by the absence of the secured
  reporting gate. The **shorts public lane** is protection *deliberately declined*: shorts are meant to be
  opened, shared, embedded and crawled, so a token would break every one of those. Do not "fix" a short by
  putting it behind `/playback`, and do not cite shorts as precedent for leaving a class recording public.
  The consequence to remember is that a shorts URL, once out, is permanent and hotlinkable — which is why
  the admin dialog has to say so, and why that surface must not become a convenient place to put a paid
  recording.
- **stream-status is NOT live-only.** The video-transcoder `CONTEXT.md` flags that an old handoff (§8) wrongly
  scoped `stream-status` to the live transcoder; the recorded 1A path must also call it for pre-recorded
  (never-live) classes, or their HLS is unreachable. This is the crux of the secured-prerecorded-playback slice.
