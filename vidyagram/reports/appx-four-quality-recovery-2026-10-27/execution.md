# Four playlist-blocked videos: bounded alternate-quality recovery

Human authorization: “bring the other 4 then”, after discussion of importing only complete alternative qualities. Tenant Vidyagram 781, AppX org 2177599, Mongo vidyagramdb, output recordedvideos-vidyagram.

Exact scope: काल (course 22 row 16294), CLASS 01 (22 / 15410), Size And Location (Practice Class) (22 / 15409), Demo 01 (Percentage) (24 / 17883). The first three have unavailable advertised 1080p playlists; the fourth has unavailable 240p. Initial scans additionally found internal segment gaps in some remaining qualities. Consequently each quality must qualify independently.

Read-only source proof uses the maintained AppX session in memory, only as a cookie to HTTPS cms.appx.co.in. Media URLs receive no session cookie. Full inventories and 1024-byte media signatures are checked, with repeat confirmation of 404s. A completed quality before the first failed quality in the prior sequential scan can be reused only with an identical inventory hash and no prioritized out-of-order reference. Other qualities are checked independently. Missing pieces are never skipped within a selected quality.

The executor captures protected full beforeimages, checks original job byte equality, identity and active visibility, re-mints a source URL and compares inventory hashes. Each qualified job is claimed directly with a compare-and-set guard, preserving its ID and legacy unique source pair. An isolated one-shot command uses the existing 781 image's dependencies to copy only selected complete qualities. It probes actual video dimensions for the master, validates media bytes while copying, writes the master only after all selected copies succeed, then uses existing secured class and completion callbacks. URLs travel only through in-memory SSH stdin. No persistent worker config, deployment, queue loop, course placement, catalogue ledger or student progress changes are part of this recovery. Failures are held dead for review rather than put in an automatic retry loop.

Validation: mocked worker execution verified that omitted qualities are absent from the published master and that a copy failure cannot publish or complete. Post-recovery checks must cover origin storage, signed production admin-preview playback, and preservation of course placements, catalogue ledgers and the other 32 blocked jobs.

The first command invocation stopped before worker execution because the remote shell removed JavaScript string quotes. The first job was returned to dead with a bounded operator error; an audit confirmed no Class, course placement, catalogue ledger or other selected job changed. The command quoting was corrected and a harmless remote evaluation passed. An exact resume guard compared the failed job against its saved operation and every Class/other job against the original beforeimages. The original beforeimages and failed command evidence were retained; a separate single-use resume snapshot/marker records the correction.

Canary outcome: काल copied both selected qualities (actual 144p and 480p), completed its secured callback, passed origin first/middle/last samples and signed production admin-preview playback. Only after that gate passed were the remaining three allowed to proceed.
